# Deployment Guide – Bharat Motors Car Dealership

This guide explains how to deploy the full-stack Car Dealership application to **Render** as a unified single-service web application.

---

## Architecture Overview

The application is configured to build and run as a single, self-contained Node.js service:
- **Frontend**: React 19 + TypeScript + Vite builds to static files in `frontend/dist`.
- **Backend**: Express API serves both the REST endpoints (`/api/*`) and the compiled frontend single-page application (`/*`).
- **Database**: SQLite file (`dealership.db`) with automatic schema initialization and idempotent seeding.
- **Benefits**:
  - No CORS setup or cross-domain issues.
  - Zero reverse-proxy configuration required.
  - Runs in a single free or low-cost container.

## Method 1: Automatic Deployment via Render Blueprint (Recommended)

The repository includes a ready-to-use [`render.yaml`](render.yaml) file.

### Steps:
1. **Push your code to GitHub**:
   ```bash
   git add .
   git commit -m "feat: configure full-stack production build and Render deployment"
   git push origin main
   ```
2. Open the **[Render Dashboard](https://dashboard.render.com/)**.
3. Click **New +** in the top navigation and select **Blueprint**.
4. Connect your GitHub repository: `AuroraDangelo/Incubyte-Assesment`.
5. Render will automatically read [`render.yaml`](render.yaml) and configure:
   - **Service Name**: `car-dealership`
   - **Environment**: Node
   - **Build Command**: `npm run install:all && npm run build`
   - **Start Command**: `npm start`
   - **Health Check**: `/api/health`
   - **Environment Variables**:
     - `NODE_ENV`: `production`
     - `JWT_SECRET`: *(cryptographically generated by Render)*
     - `ADMIN_EMAIL`: `admin@dealership.test`
     - `ADMIN_PASSWORD`: `Admin@12345`
6. Click **Apply**. Render will clone, build, seed, and launch your application!

## Method 2: Manual Web Service Setup on Render

If you prefer to configure the service manually through Render's web interface:

1. In the **Render Dashboard**, click **New +** → **Web Service**.
2. Select your GitHub repository.
3. Configure the settings:
   - **Name**: `car-dealership` (or any name you prefer)
   - **Region**: Choose the closest region (e.g., Oregon, Frankfurt, Singapore)
   - **Branch**: `main`
   - **Runtime**: `Node`
   - **Build Command**:
     ```bash
     npm run install:all && npm run build
     ```
   - **Start Command**:
     ```bash
     npm start
     ```
   - **Instance Type**: `Free`
4. Expand **Advanced** → **Add Environment Variables**:
   | Key | Value | Note |
   | --- | --- | --- |
   | `NODE_ENV` | `production` | Enables production mode |
   | `JWT_SECRET` | *(Random 32+ character string)* | e.g., run `openssl rand -hex 32` or type a secret |
   | `ADMIN_EMAIL` | `admin@dealership.test` | Default admin email |
   | `ADMIN_PASSWORD` | `Admin@12345` | Default admin password |
5. Click **Create Web Service**.

## Verifying the Deployment

Once Render finishes the build (usually 1–2 minutes), your service URL will be live at:
`https://<your-service-name>.onrender.com`

### Verification Checklist:
1. **Health Check**:
   Visit `https://<your-service-name>.onrender.com/api/health` → Should return `{"status":"ok"}`.
2. **Frontend UI**:
   Visit the root URL → You should see the sleek Bharat Motors landing page with showroom inventory.
3. **Admin Login**:
   Click **Sign In** and log in with:
   - **Email**: `admin@dealership.test`
   - **Password**: `Admin@12345`
   - Verify that admin controls appear (e.g., **Add Vehicle**, **Restock**, and **Delete**).
4. **Customer Features**:
   - Register a new user account.
   - Search and filter cars by category (e.g. Electric, SUV).
   - Test purchasing a car to confirm real-time inventory decrement.

## Database Persistence Notes

- **Render Free Tier**:
  Render's free tier uses an ephemeral filesystem. If the container restarts or redeploys, a fresh database is automatically initialized and seeded with the default admin and showroom cars.
- **Persistent Disk (Render Starter / Paid Tier)**:
  To keep user registrations and updated inventory across redeploys on Render:
  1. In your Web Service settings, go to **Disks** → **Add Disk**.
  2. Set **Mount Path** to `/var/data` (1 GB size is plenty).
  3. Add an environment variable:
     - `DB_PATH`: `/var/data/dealership.db`
  4. Save changes. The app will automatically store the SQLite database on the persistent volume.
